Build profile
-------------
This is an LGPL-only build. It does not pass --enable-gpl,
--enable-version3, or --enable-nonfree, and it does not link x264, libvpx,
libmp3lame. It links the pinned BSD-2-Clause OpenH264 library statically for
H.264 encoding on all platforms. The corresponding OpenH264 source archive
and COPYRIGHT/LICENSE text are included in ffmpeg-source/. FFmpeg's own libraries are
linked statically into the two tools. On the default Linux build, the tools
use the platform's dynamic libc, libm, and zlib runtime (the exact runtime
dependencies are recorded by the build output); those operating-system
libraries are not part of this package. The optional --static-linux build
also links libc when a suitable target toolchain provides it, but that mode
requires the target platform's corresponding relink/source materials before
redistribution. The following native functionality is intentionally enabled:

* demux/mux for common local MP4/MOV, Matroska/WebM, MPEG-TS, AVI, MP3, WAV,
  FLAC, Ogg, and image-pipe files;
* OpenH264 H.264 encoder, plus native MPEG-4 Part 2 (fixtures) and AAC encoders;
* native H.264, HEVC, MPEG-1/2/4, MJPEG, VP8, and VP9 decoders;
* native MP3 and PCM decoders plus PCM encoders;
* the filters needed by Slicer for exact trims and still-frame previews,
  including trim, atrim, setpts, asetpts, scale, format, aresample, and the
  testsrc2 fixture; and
* native GIF export through the GIF muxer/encoder and the palettegen,
  paletteuse, split, and fps filters. These filters are part of FFmpeg's
  LGPL source profile and do not add an external codec dependency.

FFmpeg has no native VP8/VP9 or MP3 encoder. VP8/VP9 encoding would require
libvpx, and MP3 encoding would require libmp3lame; those are separate optional
dependencies and are deliberately not hidden in the LGPL bundle. H.264
encoding through x264 is also omitted because FFmpeg documents x264 as GPL.
